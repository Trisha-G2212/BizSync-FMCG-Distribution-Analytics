# BizSync — API Documentation

Full interactive documentation is auto-generated by FastAPI and available
at `/docs` (Swagger UI) or `/redoc` whenever the backend is running. This
document is a organized reference alongside it.

All endpoints are prefixed with `/api`. All endpoints except `/health` and
`/auth/login` require a `Authorization: Bearer <token>` header.

## Authentication
| Method | Path | Description | Auth |
|---|---|---|---|
| POST | /auth/login | Exchange email/password for a JWT | none |
| GET | /auth/me | Return the current authenticated user | any |

## Products
| Method | Path | Description | Auth |
|---|---|---|---|
| GET | /products | Paginated list, filterable by search/category/active | any |
| POST | /products | Create a product | ADMIN, SALES_MANAGER |
| GET | /products/{id} | Get one product | any |
| PUT | /products/{id} | Update a product | ADMIN, SALES_MANAGER |
| DELETE | /products/{id} | Deactivate (soft-delete) a product | ADMIN |

Errors: 409 on duplicate `product_code`; 404 if not found; 422 on invalid
field values (e.g. non-positive price).

## Inventory
| Method | Path | Description | Auth |
|---|---|---|---|
| GET | /inventory | Paginated list, filterable by distributor/product/low_stock_only | any |

Read-only by design — stock only changes via order confirmation or Excel
import, always with an audit trail (see Orders and Excel Import below).

## Orders
| Method | Path | Description | Auth |
|---|---|---|---|
| GET | /orders | Paginated list, filterable by status/retailer/distributor | any |
| POST | /orders | Create an order (status starts PENDING) | ADMIN, SALES_MANAGER, SALES_REP |
| GET | /orders/{id} | Get one order with line items | any |
| PATCH | /orders/{id}/status | Transition order status | ADMIN, SALES_MANAGER |

Valid status transitions: `PENDING → CONFIRMED → PROCESSING → SHIPPED →
DELIVERED`, with `CANCELLED` reachable from any pre-shipment state.
Confirming an order locks and validates inventory for every line item
(`SELECT ... FOR UPDATE`) before deducting stock — see `docs/architecture.md`
for the full transaction-safety explanation.

Errors: 409 on an invalid status transition or insufficient inventory
(with a message stating exact available vs. requested quantity); 422 if
`retailer_id`/`distributor_id`/any `product_id` doesn't exist.

## Excel Import
| Method | Path | Description | Auth |
|---|---|---|---|
| POST | /import/{entity} | Upload an Excel file. `entity` is one of: products, retailers, sales, inventory | ADMIN, SALES_MANAGER |

Response is an `ImportSummary`: `records_processed`,
`successfully_imported`, `failed`, `duplicates`, `invalid_rows`, and an
`errors` array of `{row, message}`. See `docs/troubleshooting.md` for the
real bugs found while building this validation pipeline.

## Analytics Dashboard
| Method | Path | Description | Auth |
|---|---|---|---|
| GET | /dashboard/summary | Revenue, order/product/retailer/distributor counts, low-stock and pending-order counts | any |
| GET | /dashboard/sales-trend | Revenue over time, daily or monthly granularity | any |
| GET | /dashboard/top-products | Top N products by revenue | any |
| GET | /dashboard/top-retailers | Top N retailers by revenue | any |
| GET | /dashboard/category-performance | Revenue/quantity by product category | any |
| GET | /dashboard/distributor-performance | Revenue, orders, retailer count, inventory value per distributor | any |

Every figure is computed via SQL aggregation (`SUM`/`COUNT`/`GROUP BY`),
never by loading raw rows into Python — see `docs/architecture.md`.

## Troubleshooting
| Method | Path | Description | Auth |
|---|---|---|---|
| GET | /issues | Paginated list, filterable by status/severity/module | any |
| POST | /issues | Report an issue (any authenticated user) | any |
| GET | /issues/{id} | Get one issue | any |
| PUT | /issues/{id} | Update status/root_cause/resolution | ADMIN, ANALYST |

`resolved_at` is set automatically by the server the moment `status`
transitions to `RESOLVED`, and cleared if the issue is reopened — never
sent by the client.

## Standard error responses

| Status | Meaning |
|---|---|
| 400 | Malformed request (e.g. wrong file type on import) |
| 401 | Missing or invalid authentication token |
| 403 | Authenticated, but the user's role isn't permitted |
| 404 | Resource not found |
| 409 | Conflict (duplicate code, invalid state transition, insufficient inventory) |
| 422 | Validation failure (bad field values, a referenced ID doesn't exist) |
| 500 | Unexpected server error (never exposes raw database errors — see `docs/troubleshooting.md`) |
